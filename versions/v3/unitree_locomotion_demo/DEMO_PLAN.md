# Unitree Locomotion Demo Plan

This folder is for **demo-only** locomotion videos generated by running
Unitree's open-source G1 MuJoCo policy. It should not be used as paper evidence
that our controller solves dynamic walking.

The paper focuses on interaction dynamics for floating-base whole-body
manipulation. Walking, gait scheduling, and low-level leg tracking come from
Unitree RL Gym. The v3 correction module is an add-on command shaper, not the
gait generator.

## Demo Message

The demo should communicate one idea:

> Unitree's open-source locomotion policy handles walking, while the v3
> interaction-dynamics code adds disturbance estimation, load preview, and
> high-level task/body correction on top.

The demo must not claim that the v3 controller itself solves dynamic walking.

## Architecture

```text
Unitree locomotion base
  - gait schedule
  - walking / running / stopping
  - balance recovery
  - contact switching

        + measured state / command interface
        + optional external force or task load estimate

V3 correction module
  - body-port disturbance observer
  - task-port disturbance observer
  - planned-load preview
  - residual CoM / trunk / hand correction

        -> high-level correction command

Unitree locomotion stack / whole-body executor
```

The preferred interface is **high-level correction**, not raw joint torque:

- CoM velocity correction;
- pelvis/trunk pose correction;
- body lean correction;
- task-space hand reference correction;
- planned external-load estimate, if Unitree exposes a wrench-aware interface.

Do not inject joint torques underneath the Unitree controller unless the SDK
explicitly exposes a supported torque/current interface with safety limits.

## Demo Videos

### D0: Baseline Unitree G1 Walking

Goal: show the Unitree open-source locomotion controller walking without
our layer.

Inputs:

- generated Unitree open-source MuJoCo run;
- commanded velocity;
- base pose and estimated CoM, if available.

Overlay:

- "D0 Baseline: Unitree G1 walking";
- commanded speed;
- no interaction correction.

### D1: Push Test With Unitree Policy Only

Goal: show the disturbance problem.

Inputs:

- same locomotion command as D0;
- external lateral push or carried-load disturbance;
- high-level correction disabled.

Metrics:

- lateral CoM or pelvis deviation;
- torso roll/pitch;
- recovery time;
- detected disturbance score, if observer is still run passively.

### D2: Push Test With Interaction Dynamics MPC Correction

Goal: show the value of the Interaction Dynamics MPC correction signal.

Inputs:

- same locomotion command and same disturbance as D1;
- Interaction Dynamics MPC correction enabled.

Metrics:

- lateral CoM/pelvis deviation reduction;
- recovery time reduction;
- body disturbance estimate;
- no change to commanded gait schedule.

### D3: Loco-Manipulation Load Preview

Goal: show task interaction during locomotion.

Scenario options:

- robot walks while carrying/pushing a load;
- robot walks while the hand receives a planned lateral force;
- robot walks while the hand follows a target and a human pushes/pulls.

Comparison:

- observer-only rejection;
- planned-load preview plus observer.

Metrics:

- hand tracking error;
- lateral pelvis/CoM error;
- estimated disturbance;
- preview command.

## What To Record

For every clip, save:

```text
time
base position / orientation
commanded velocity
estimated CoM or pelvis position
torso roll/pitch
left/right foot contact state, if available
external disturbance schedule, if scripted
observer disturbance estimate
high-level correction command
fall / safety status
```

## Recommended Video Layout

Use a split-screen format:

```text
left:  robot video / MuJoCo viewport
right: live plots
       - commanded speed
       - lateral CoM/pelvis error
       - torso roll/pitch
       - disturbance estimate / innovation
       - correction command
```

Each video should include an explicit label:

- "D0 Baseline", "D1 Push: Unitree only", "D2 Push: correction enabled", or "D3 Preview";
- "correction off" or "correction on";
- "demo only; locomotion supplied by Unitree stack";
- "not paper evidence for v3 walking controller".

## Minimal Acceptance Criteria

For a demo clip to be useful:

- it is generated by the Unitree open-source G1 MuJoCo policy;
- walking/running is not attributed to the v3 correction module;
- the disturbance schedule is identical between off/on comparisons;
- metrics are computed from logs, not only visual appearance;
- the final video label makes the claim boundary obvious.

## Current Local Generator

The raw D0-D3 scene runs are generated locally from Unitree's open-source G1
MuJoCo policy:

```bash
mjpython scripts/generate_all_open_source_videos.py
```

The retained videos are the three final comparisons:

- `results/unitree_d0_baseline_comparison.mp4`
- `results/unitree_d1_d2_push_comparison.mp4`
- `results/unitree_d3_preview_comparison.mp4`

The raw scene MP4s are intermediate artifacts and are deleted by the generator
unless `--keep-intermediate-videos` is used for debugging.
