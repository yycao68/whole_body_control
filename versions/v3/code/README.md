# V3 Interaction-Dynamics Uneven-Ground Benchmark

The current publication evidence is generated by run_uneven_ground_benchmark.py.
It contains 160 torque-level Unitree G1 simulations: four terrains, four
controllers, and ten paired seeds per cell. The authoritative record is
results/uneven_ground_benchmark.json; representative seed-4200 histories are
stored as 16 compressed NPZ logs.

To reproduce the current paper evidence from the repository root, run the
following commands in order:

    MPLCONFIGDIR=/private/tmp/mplconfig XDG_CACHE_HOME=/private/tmp/cache python3 whole_body_control/versions/v3/code/run_uneven_ground_benchmark.py --trials 10 --seed 4200 --no-logs
    MPLCONFIGDIR=/private/tmp/mplconfig XDG_CACHE_HOME=/private/tmp/cache python3 whole_body_control/versions/v3/code/run_uneven_ground_benchmark.py --trials 1 --seed 4200 --artifact uneven_ground_representative.json
    MPLCONFIGDIR=/private/tmp/mplconfig XDG_CACHE_HOME=/private/tmp/cache python3 whole_body_control/versions/v3/code/make_uneven_ground_figures.py
    python3 whole_body_control/versions/v3/code/verify_interaction_paper_claims.py

The final command requires all 160 finite trials, the complete seed/cell matrix,
zero QP fallbacks, and all four derived figures. The result is mixed: residual
augmentation improves obstacle peak error but not tracking uniformly, and the
realization-feedback ablation is unfavorable. The Python WBC also misses its
simulated 500 Hz wall-clock deadline. These boundaries are reported in the
paper rather than hidden.

## Legacy authority-study documentation

This folder contains the implementation used by *Interaction Dynamics for
Floating-Base Whole-Body Manipulation*. The current paper evidence concerns a
constant canonical predictor with realization-informed residual-command bounds.

## Current implementation

- `normalized_mpc.py` implements the dimension-generic canonical double
  integrator. `update_input_box(lower, upper)` accepts a box frozen over the
  horizon or arrays of shape `(horizon, dim)` for scheduled bounds. Updating a
  box does not rebuild the dynamics or cost.
- `run_g1_torque_realizer_benchmark.py` provides the torque-actuated G1 model
  and the present-sample inverse-dynamics/contact QP. It exposes the solved
  generalized acceleration, torque, contact force, equality residual, body and
  task realization residuals, and the active one-step acceleration bounds.
- `realization_authority.py` searches the actual hard-constrained QP along the
  four signed planar command rays, using the requested-versus-realized
  acceleration residual as the admissibility test. It then validates Cartesian
  corners and shrinks the box when needed. It does not extrapolate a local QP
  sensitivity through active-set changes.
- `run_authority_benchmarks.py` is the current paper benchmark and figure
  generator.
- `run_authority_transition.py` prepares support in measured double support,
  gates lift-off on a valid candidate single-support query, switches the
  realizer from measured contacts, and verifies sustained double support after
  touchdown.
- `verify_v3_artifacts.py` is the current default evidence gate.

The exact-query estimator is evaluated at a 20 ms MPC period in the lateral
step and a 40 ms period in the transition; the inverse-dynamics realizer still
runs at the 1 ms simulation step. Wall-clock query time is recorded but is not
charged to simulated time. The current direct search is non-real-time; a
faster conservative surrogate or asynchronous update is required for control.

## Evidence boundaries

The evaluated authority is the planar body-priority slice with the hand task
held at its nominal damping request. It is not yet a coupled body-task authority
polytope. The single-support query at the unprepared double-support state is
intentionally rejected; after state preparation, the same readiness logic
completes one scripted in-place double--single--double cycle. This is not a
walking result. The closed-loop comparison does not establish a tracking or
robust-fidelity advantage, and queried sets can become stale or invalid between
updates.

All current results are MuJoCo results on one Unitree G1 model. They do not
establish recursive feasibility, repeated locomotion, cross-robot performance,
or hardware robustness.

## Legacy studies

The older `run_h1_*`, `run_h3_*`, `run_h4_*`, `run_h5_*`, `run_h6_*`,
root-assisted walking, contact-transition, and Unitree-policy compatibility
scripts remain in the folder as development history. Their generated files are
not cited by the current paper, and `run_all.py` remains a legacy batch runner.
They must not be treated as evidence for online predictor authority unless they
are explicitly converted to use `PlanarBodyAuthorityEstimator` and regenerated.

## Minimum current checks

1. Exact-ZOH `A` and `B` and input-centered disturbance cancellation.
2. Runtime asymmetric and horizon-scheduled command bounds.
3. Invariance of canonical matrices and condensed Hessian under bound updates.
4. Exact-QP residual searches across realizer active-set changes.
5. Exact-realizer corner validation with the declared acceleration tolerance.
6. Empty-set handling through a zero-residual fallback and readiness refusal.
7. Requested-versus-realized acceleration logging and solver fallback logging.
8. Measured-contact single support and sustained double support after touchdown.
